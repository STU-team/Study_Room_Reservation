## 二、窗口骨架（B-4）

### 1. 入口与窗口

| 文件 | 内容 |
|---|---|
| `ui/AppMain.java` | 程序入口：系统 LAF、全局字体、`ServiceFactory.configure(Path.of("data"))`、启动时爽约扫描一次、登录窗口 |
| `ui/LoginFrame.java` | 登录窗口，820×500 固定尺寸，左侧实景图 + 右侧表单，按 `User.role` 打开对应主窗口 |
| `ui/StudentMainFrame.java` | 学生端主窗口，1050×720，3 个卡片页 |
| `ui/DutyAdminMainFrame.java` | 值班管理员主窗口，1150×750，2 个卡片页 + 左侧操作栏 |
| `ui/SysAdminMainFrame.java` | 系统管理员主窗口，1180×760，4 个卡片页 + 左侧操作栏 |

三个主窗口都设置 `setMinimumSize`，拖小后布局不塌；统一 `EXIT_ON_CLOSE`，退出登录时 `dispose()` 当前窗口再开登录页。

### 2. 公共样式层

| 文件 | 职责 |
|---|---|
| `ui/UiTheme.java` | 颜色、字体（微软雅黑）、扁平按钮（`primaryButton` / `secondaryButton` / `navButton` / `smallButton` / `sideButton`）、底部标签栏（`tabBar` / `tabButton` / `activateTab`） |
| `ui/TableFactory.java` | 表格统一外观（表头 38px、行高、居中、无网格线、列排序、超长文字自动换行）、空状态文字、座位/预约状态中文徽章 |
| `docs/assets/image.jpg` | 登录页配图 |

公共层是为解决三个窗口各自维护一套颜色常量与 `styledTable` 的重复问题而抽出的。按钮改为自绘（圆角填充 + 悬停/按下/禁用态），不依赖具体 LAF，避免换系统主题后彩色按钮变灰。

表格渲染器会对放不下的单元格自动换行：日期时间优先在空格处拆成“日期 / 时间”两行，预约号、手机号这类没有空格的字段取最均衡断点拆两行；相关长列表格行高统一为 54px，两行仍放不下时用悬浮提示显示完整值。

### 3. 启动链路

```text
AppMain.main
  ├─ 系统 LAF + UiTheme.installGlobalFonts()
  ├─ ServiceFactory.configure(Path.of("data"))
  ├─ ReservationService.handleNoShow(now)   // 启动时补扫一次
  ├─ 全局守护 Timer：每 60 分钟再扫一次
  └─ SwingUtilities.invokeLater → new LoginFrame().setVisible(true)
        └─ 登录成功 → 按 role 打开 Student / DutyAdmin / SysAdmin 主窗口
```

爽约扫描放在 `AppMain` 而不是每个主窗口：窗口反复登录会重复创建 `javax.swing.Timer`，导致同一时刻多次扫描；全局只保留一个守护线程更稳。该取舍与 `对接-A6到后续B.md` 建议的“挂主窗体”不同，但调用契约不变，见第五节第 6 条。

### 4. 页面布局

三个主窗口统一为 `BorderLayout`：`NORTH` 顶部导航，`CENTER` 中间区域，`SOUTH` 底部标签栏；中间再按角色加左侧操作栏。

| 窗口 | 顶部导航 | 左侧操作栏 | 卡片页（底部标签顺序） |
|---|---|---|---|
| 学生端 | 信用分、用户名、退出 | 无 | 座位总览 / 预约座位 / 我的预约 |
| 值班管理员 | 用户名、退出 | 签到登记、签退释放、预约搜索、刷新列表 | 全部预约 / 在座名单 |
| 系统管理员 | 爽约扫描、用户名、退出 | 修改座位状态、信用分明细、刷新全部 | 座位管理 / 全部预约 / 在座名单 / 学生信用分 |

页面切换用 `CardLayout` + `switchTab(card)`：`cardLayout.show(...)` 后调用 `UiTheme.activateTab(bottomTabBar, index)` 同步底部标签高亮，再按卡片刷新对应表格。卡片名与标签顺序由各窗口的 `CARDS` 常量维护，避免两处索引写死后错位。

学生端骨架示意：

```text
│ 自习室预约系统        信用分：100 | 20240001 退出 │
├──────────────────────────────────────────────┤
│                                              │
│              CardLayout 卡片区                │
│        座位总览 / 预约座位 / 我的预约           │
│                                              │
├──────────────────────────────────────────────┤
│  座位总览         预约座位         我的预约      │
└──────────────────────────────────────────────┘
```

### 5. 登录窗口

- 左侧 400×500 图片面板按“铺满裁切”绘制，不拉伸变形；底部叠加深色渐变保证标语可读，图片缺失时退化为纯色 + 默认标语。
- 右侧 `GridBagLayout` 表单：标题、副标题、用户名、密码、登录按钮、两行提示（学生用学号登录，`duty` / `admin` 为管理员，初始密码 `123456`）。
- 登录按钮设为默认按钮（回车提交），窗口打开后焦点落在用户名框；登录失败清空密码并重新聚焦。

| 提交预约 | `doReserve` | `studentService.findByStudentId(username)` → `reserve(seatNo, student, date, start, end)` | 预约号 + 签到截止时间弹窗 |
| 取消预约 | `doCancel` | `reservationService.cancelReservation(resNo)` | 仅 `BOOKED` 行可点 |

| 信用分显示 | `refreshCreditDisplay` | `studentService.findByStudentId(username)` | 分数 < 80 时标黄 |

### 3. 关键交互

#### 预约页时段联动

- 日期下拉只放今天起 7 天，与契约“最多提前 7 天”一致，正常情况下不会触发 `PARAM`。
- 选“今天”时，开始时段只保留当前时刻之后的半小时刻度；当天已无可选时段时两个下拉框为空，点搜索给出“今日已没有可预约的时段，请选择之后的日期”，不会把空值传给 Service。
- 结束时段始终大于开始时段；切换日期时先记住原选择，若原选择已不在新列表中则回退到第一个可选值，避免 `setSelectedItem` 留下非法选中项。
- 预约成功后立即从结果表移除该座位，再 `refreshAll()`，防止连点造成重复提交。

#### 管理端快捷操作

- **全部预约**双击：`BOOKED → 签到`，`CHECKED_IN → 签退`，其余状态不响应。
- **在座名单**双击：直接对该预约号签退。
- **座位管理**双击：打开状态修改对话框。
- **学生信用分**双击：打开只读明细。
- 侧栏按钮可能作用于不可见的卡片，处理函数先 `ensureAllTab()` / `ensureTab(card)` 切回目标页，再读取选中行，避免“操作了上一页的选中行”。

#### 签退时间

签退不再默认取当前时间，而是弹出 `JSpinner`（`SpinnerDateModel` + `HH:mm` 编辑器），管理员可补录实际离开时刻：

```java
LocalTime actualEnd = LocalTime.parse(SDF_TIME.format((Date) spinner.getValue()), TIME_FMT);
CheckinRecord record = reservationService.signOut(resNo, actualEnd);
```

`signOut` 返回的 `penalty` 为 1 时，成功弹窗追加“超时扣分：1 分”。界面不自行判断是否超时，也不自行减分。

### 4. 异常处理与刷新

统一 `catch (BusinessException e)`，用 `JOptionPane` 显示 `e.getMessage()`；除 `PARAM` 的格式兜底外不弹堆栈。主要分支：

| 场景 | 处理 |
|---|---|
| 登录失败（`AUTH_FAILED`） | 停留登录页，清空密码并聚焦 |
| 信用分不足（`CREDIT_LOW`） | 预约页弹窗显示 Service 文案，座位状态不变 |
| 座位不可用/冲突（`SEAT_UNAVAILABLE` / `SEAT_CONFLICT`） | 弹窗提示，保留当前搜索结果，用户可换座位/时段 |
| 状态不允许（`STATE`） | 提示后刷新对应列表，避免界面停留在过期状态 |
| 超过签到截止（`DEADLINE`） | 提示后刷新，预约会显示为爽约 |
| 预约号不存在（`NOT_FOUND`） | 清空表格并显示“没有找到该预约号” |
| 座位使用中（`SEAT_IN_USE`） | 原样显示“座位使用中，须先办理签退”，随后刷新座位表 |
| 日期/时间格式异常 | `DateTimeParseException` 单独兜底，提示重新选择 |

界面侧的**前置校验**只做“避免明显无效调用”，不复制业务规则：未选中行、未选完整时段、非 `BOOKED`/`CHECKED_IN` 状态直接提示；信用分门槛、截止时间、扣分数值仍以 Service 为准。

刷新矩阵：

| 操作 | 刷新范围 |
|---|---|
| 预约成功 | 座位总览、我的预约、信用分 |
| 取消预约 | 座位总览、我的预约（失败时只刷我的预约） |
| 签到成功/失败 | 全部预约、在座名单 |
| 签退成功/失败 | 全部预约、在座名单 |
| 爽约扫描 | 座位管理、全部预约、在座名单、学生信用分 |
| 修改座位状态 | 四个表格全刷；失败时只刷座位表 |
| 切换底部标签 | 只刷当前卡片对应的表格 |

刷新一律重新调查询方法重建 `DefaultTableModel`，不在界面维护增量状态，CSV 是唯一数据源。

## 四、与契约/对接文档的一致性

| 约定 | 落地 |
|---|---|
| 界面只通过 `ServiceFactory` 取服务 | 各窗口的 Service 字段均为接口类型，构造时调用 `ServiceFactory.getXxxService()`，无 `new XxxImpl`、无 DAO/CSV 访问 |
| `User.getUsername()` 即学生学号 | 学生端“我的预约”“信用分”均以 `currentUser.getUsername()` 作为学号 |
| 状态中文映射 | 集中在 `TableFactory`：座位 可用/已预约/使用中/维修；预约 待签到/使用中/已签退/已取消/爽约 |
| 时间展示格式 | `SimpleDateFormat("yyyy-MM-dd HH:mm")`；只显示时刻用 `"HH:mm"` |
| 区域下拉框 | 无独立区域接口，用 `seatService.listAllSeats()` 的 `getRoomName()` 去重生成，首项为“不限” |
| 信用分只读 | 学生端只显示分数，低于 80 时标黄；系统管理员只查看明细，不提供改分入口 |

## 五、实现取舍

1. **在座名单一次建索引**：`listSeated()` 只返回签到记录，需要补座位/姓名/手机。实现上先 `listAllReservations()` 建 `Map<resNo, Reservation>`，再遍历签到记录，查询次数从逐条回查的 N+1 降到 2 次。
2. **签到提前量限制放在界面**：Service 只校验签到截止时间，界面额外拒绝“早于开始时间 5 分钟以上”的签到，避免演示时误点。该 5 分钟是界面操作口径，不是契约规则，调整只需改 `DutyAdminMainFrame.doSignIn`。
3. **信用分明细只读**：`StudentServiceImpl` 不提供改分接口，界面只展示当前分数、预约资格与扣分规则，并注明“由系统在签退和爽约扫描时自动结算”。
4. **座位状态候选排除当前值**：下拉框不列出当前状态，减少误操作。A-10 已按联调问题单在契约 v1.3 收紧 `SeatServiceImpl.updateSeatStatus`：`AVAILABLE ↔ CLOSED` 允许，`OCCUPIED` / `RESERVED` 一律由 Service 拒绝，界面保留原候选，失败时原样显示 Service 文案，以便演示异常提示。本轮不做候选收窄，后续如需要再按矩阵裁剪下拉项。
5. **状态列渲染与业务判断分离**：表格模型里存枚举原值，`TableFactory` 渲染器负责中文与配色；双击判断仍比较枚举（`== ReservationStatus.BOOKED`），不受排序影响。
6. **全局爽约扫描**：`AppMain` 启动补扫一次 + 守护定时器每 60 分钟一次，与登录窗口解耦；`SysAdminMainFrame` 的“爽约扫描”按钮用于演示时手动触发。
7. **“我的预约”座位状态一次建索引**：v1.3 起“我的预约”表增加“座位状态”列。刷新时先 `listReservations(username)`，再取一次 `listAllSeats()` 建 `Map<座位号, SeatStatus>` 回填，避免逐行查座位；状态列复用 `TableFactory.seatStatusRenderer()`。列数变化后，取消校验与渲染器列索引同步改为 8 与 2/8。

## 七、遗留与后续

1. **爽约定时器位置**：按全局守护 `java.util.Timer` 实现（启动一次 + 每 60 分钟），未采用“每个主窗口一个 `javax.swing.Timer`”。这样窗口切换/重登不会叠加扫描任务；如 A 侧坚持定时器跟随窗口生命周期，再调整。
2. **签退时间只有 `HH:mm`**：`signOut` 的 `actualEnd` 是 `LocalTime`，跨零点签退无法表达日期。当前演示场景不涉及，若需要跨日签退，需按 `CONTRACT-CHANGE` 调整接口为 `LocalDateTime`。
3. **提前 5 分钟签到是界面规则**：Service 不拦截提前签到，联调时若 A 侧要求统一口径，需确认是否下沉到 Service。
4. **无界面自动化测试**：现有 43 个用例覆盖 Service/DAO，Swing 部分只做了构造冒烟与手工点击；如需回归，可后续补 AssertJ-Swing 或按联调清单手工验收。
5. **座位单值状态限制已解决**：A-10 在契约 v1.3 中把座位 `status` 改为汇总状态，可用性按所选时段与 `BOOKED` / `CHECKED_IN` 判重叠，同一座位可存在多条不重叠预约；`reserve` / `cancel` / `signIn` / `signOut` / `handleNoShow` 之后统一调 `refreshSeatSummary` 重算。界面按新口径原样展示，不自行推断可用性。
6. **权限只到窗口级**：角色决定打开哪个主窗口，窗口内部不再做细粒度权限校验；契约未要求服务端鉴权。
7. **运行截图已补齐**：“我的预约”座位状态列完成后，B-6 的 6 张运行截图已放入 `docs/assets/`：`B4_登录界面.png`、`B4_学生端座位总览.png`、`B5_预约成功弹窗.png`、`B5_我的预约_座位状态.png`、`B5_签退成功.png`、`B5_信用分明细.png`，与进度看板截图清单一致；本记录暂不嵌图。
