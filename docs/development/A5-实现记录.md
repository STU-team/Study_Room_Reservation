# A-5 实现记录

> **任务**：A-5 后端实体与本地 CSV 持久层
> **依据**：分工说明、接口契约 v0.6、A-3 最终类图、A-4 最终状态图
> **当前状态**：已完成（实体、7 张 CSV 的读写实现、单元测试全部通过）
> **版本**：v1.2（2026-11-06）
> **原则**：实体与 Service 字段以 A-3 最终类图与契约为准；CSV 表头严格按契约第八节；两者之间的字段落差由 DAO 做映射消化；契约变更只在确有业务需要时按 `CONTRACT-CHANGE` 进行（v0.7 仅补两个 DAO 接口）。

## 一、交付内容

### 1. 枚举（4 个）

`Role`、`SeatStatus`、`ReservationStatus`、`CreditChangeReason`，取值与契约第四节完全一致，含 `NO_SHOW`。

### 2. 实体（7 个）

`User`、`Student`、`SeatType`、`Seat`、`Reservation`、`CheckinRecord`、`CreditScoreLog`。

`Reservation` 实现 A-4 状态图的四种动作，返回类型按类图：

| 方法 | 合法源状态 | 结果 |
|---|---|---|
| `cancel()` | `BOOKED` | `CANCELLED`，返回 true；其余状态返回 false |
| `checkIn()` | `BOOKED` | `CHECKED_IN`，返回 true；其余状态返回 false |
| `checkOut()` | `CHECKED_IN` | `CHECKED_OUT`，返回 true；其余状态返回 false |
| `handleNoShow()` | 仅 `BOOKED` | `NO_SHOW`；非 `BOOKED` 抛 `IllegalStateException` |

`Seat.updateStatus(newStatus)` 只负责赋值与判空，状态转移是否合法由 A-6 `SeatService` 按状态图校验。座位释放、信用分调整、流水写入均不在实体里做，留给 Service 编排。

### 3. 基础设施

- `CsvUtil`：UTF-8、逗号/双引号/换行转义、整表读写、追加、表头校验、临时文件原子替换、BOM 剥离。
- `CsvMapper`：契约第八节日期时间格式（`yyyy-MM-dd HH:mm`）、业务编号到 Long 主键的稳定散列、整数与空值处理。
- `DataInitializer`：按契约 v0.6 初始化七张表表头，先全量校验再创建，不覆盖已有数据，表头不符时报错退出。

### 4. 持久层（7 张 CSV 全覆盖）

| 契约接口 | 实现类 | 表 |
|---|---|---|
| `SeatDao` | `CsvSeatDao` | `seats.csv` |
| `ReservationDao` | `CsvReservationDao` | `reservations.csv` |
| `StudentDao` | `CsvStudentDao` | `students.csv` |
| `UserDao` | `CsvUserDao` | `users.csv` |
| `CheckinRecordDao` | `CsvCheckinRecordDao` | `checkin_records.csv` |
| 契约未声明接口 | `CsvCreditScoreLogDao`（`save` / `findByStudentId` / `findAll`） | `credit_score_logs.csv` |
| 契约未声明接口 | `CsvSeatTypeDao`（`findAll` / `findByTypeName`） | `seat_types.csv`（`seatCount` 实时统计） |

这两个类原本是独立实现类，契约 v0.7 已在第七节补上 `CreditScoreLogDao`、`SeatTypeDao` 两个接口，现在分别 implements 对应接口，第七节接口与第八节七张表一一对应。

## 二、字段落差与映射约定

契约第八节的 CSV 表头停留在早期字段（业务编号为主），A-3 类图是主键 + 完整时间字段。**契约不改，改为在 DAO 层做双向映射**：

| 实体字段 | CSV 对应 | 映射方式 |
|---|---|---|
| `Seat.seatId` | 无列 | 由 `seatNo` 稳定散列（`CsvMapper.stableId`），同一座位号恒等，重启可还原 |
| `Seat.roomName` | `typeName` | 同义复用：读入 `roomName = typeName`，写回 `typeName = roomName` |
| `SeatType.seatCount` | `seatCount` 列 | 派生值，权威值取 `CsvSeatDao.countByTypeName` 实时统计，列值仅冗余 |
| `User.userId` | 无列 | 由 `username` 稳定散列 |
| `User.name` | 无列 | 读入时取 `username` 作为显示名 |
| `Reservation.resNo` | `resNo` | 直接对应；实体补 `resNo` 字段（契约第七节 `findByNo(String resNo)`、`nextResNo()` 与第八节均以它为主键） |
| `Reservation.reservationId` | 无列 | 由 `resNo` 稳定散列 |
| `Reservation.seatId` / `userId` | 无列 | 分别由 `seatNo`、`studentId` 散列，与 Seat/User 主键规则一致 |
| `Reservation.createTime` | 无列 | 取 `resDate + startTime`（预约生成时刻与开始时刻同值），**这是唯一有损项** |
| `Reservation.signInDeadline` | 无列 | 按契约第二节固定规则取 `startTime + 15 分钟`，无损还原 |
| `Reservation.studentId` / `seatNo` | `studentId` / `seatNo` | 实体补这两个业务编号字段，写回 CSV 用 |
| `Reservation.studentName` / `phone` | `studentName` / `phone` | 写入时按 `studentId` 反查 `students.csv` 生成快照 |
| `CheckinRecord.resNo` | `resNo` | 实体补字段，否则 `findByResNo` 无法支持 |
| `CheckinRecord.createTime` | `createTime` | 实体补字段，写入时缺省取当前时间 |

**实体新增字段清单**（均是为满足契约第七/八节而补，A-3 类图未画）：`Reservation.resNo`、`Reservation.studentId`、`Reservation.seatNo`、`CheckinRecord.resNo`、`CheckinRecord.createTime`。

## 四、遗留与后续

1. **已知限制（不补列）**：`Reservation.createTime` 在 CSV 中无列，重载后等于 `startTime`。核对 A-1~A-4 后确认，该属性只在 A-3 类图中作为“预约提交时间”列出，用例叙述、CIM 活动图、时序图、Service 接口与界面流程均未使用，故本阶段不补列。
2. **契约 v0.7**：第七节已补 `CreditScoreLogDao`、`SeatTypeDao`，实现类已改为 implements；其余节（实体、Service、CSV 表头）保持 v0.6 原文不变。
3. **A-6 输入约定**：`Reservation` 在 `save` 前必须设置 `resNo`（可先调 `nextResNo()`）、`studentId`、`seatNo`、`startTime`、`endTime`、`status`；否则 DAO 抛 `IllegalArgumentException` / `DataAccessException`。
4. A-5 不实现业务编排，Service 层（A-6）负责状态图校验、信用分计算与流水写入。
