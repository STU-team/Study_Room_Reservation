## 一、总体约定

1. 包根为 `com.studyroom`，分为 `entity`（实体）、`dao` + `dao.impl`（持久化）、`service` + `service.impl`（业务逻辑）、`ui`（Swing 界面）、`util`（工具）。
2. 前端只依赖 `service` 层接口，不得直接操作 DAO 或实体内部字段；后端不依赖任何 Swing 类。
3. 本系统为高校免费公共自习室，不涉及费用结算，以信用分机制约束预约行为。
4. 业务异常统一抛 `com.studyroom.service.BusinessException`（继承 `RuntimeException`，含 `code` 与 `message`），前端捕获后弹窗提示。
5. 命名约定：类名大驼峰；方法名小驼峰；座位号 `seatNo`（如 `"A01"`）；预约号 `resNo`（如 `"RES20261029001"`）。

## 二、信用分规则（已与 B 确认）

| 规则 | 取值 |
|---|---|
| 初始信用分 | 100 分 |
| 签到截止时间 | 预约开始时间 + 15 分钟（由 M01 的规则参数维护，默认 15） |
| 预约后未签到（爽约） | 扣 5 分，自动取消预约并释放座位 |
| 签到后超时未签退 | 扣 1 分，自动释放座位 |
| 禁止预约阈值 | 信用分低于 80 分时不可预约 |
| 续时功能 | 不做，到时间签退，需继续使用则重新查询并预约 |

**爽约判定方式**：由 `ReservationService.handleNoShow(now)` 统一扫描判定，凡状态为 `BOOKED` 且当前时间已超过签到截止时间的记录，逐条按爽约处理。扫描时机为系统启动时一次 + 之后定时触发，不依赖学生或管理员的界面操作，避免学生既不来签到也不取消时座位被永久占用。

| 类名 | 职责 | 关键属性 |
|---|---|---|
| `Seat` | 具体座位，承载座位状态与预约动作 | `seatNo`、`seatType`、`status` |
| `SeatType` | 座位区域定义（靠窗区/普通区/沙发区等） | `typeName`、`seatCount` |

## 六、Service 接口（前端调用入口）

```java
package com.studyroom.service;

public interface ReservationService {

    // 查询指定日期与时间段内某区域的可用座位（typeName 传 null 表示不限区域）
    List<Seat> listAvailableSeats(LocalDate date, LocalTime start, LocalTime end, String typeName);

    // 查询某个学生的全部预约记录，按预约开始时间倒序；studentId 为空抛 PARAM
    List<Reservation> listReservations(String studentId);

    // 查询全部预约记录，按预约开始时间倒序，供管理员界面展示
    List<Reservation> listAllReservations();

    // 查询当前在座记录（已签到未签退，即 actualEnd 为空的签到记录）
    List<CheckinRecord> listSeated();

    // 按预约号查单条预约（在座名单等场景补座位与预约人信息）；不存在抛 NOT_FOUND
    Reservation findReservation(String resNo) throws BusinessException;

    // 在线预约：校验信用分>=80、座位可用后生成预约记录
    Reservation reserve(String seatNo, Student student, LocalDate date, LocalTime start, LocalTime end)
            throws BusinessException;

    // 取消预约：仅允许签到前取消 BOOKED 状态的预约，释放座位
    Reservation cancelReservation(String resNo) throws BusinessException;

    // 签到登记：预约状态 BOOKED -> CHECKED_IN，座位 -> OCCUPIED
    Reservation signIn(String resNo) throws BusinessException;

    // 签退释放：释放座位，判定是否超时（实际结束>预约结束则扣学生1分），返回签退记录
    CheckinRecord signOut(String resNo, LocalTime actualEnd) throws BusinessException;

    // 爽约处理：扫描所有已过签到截止时间仍未签到的 BOOKED 预约，
    // 逐条置为 NO_SHOW（注意不是 CANCELLED，便于统计爽约率）、释放座位、
    // 扣该学生 5 分并写一条 CreditScoreLog(NO_SHOW, -5)；返回本次处理条数
    int handleNoShow(LocalDateTime now) throws BusinessException;
}
```

| 文件 | 用途 | 字段（表头） |
|---|---|---|
| `data/seats.csv` | 座位数据 | `seatNo,typeName,status` |
| `data/seat_types.csv` | 座位区域数据 | `typeName,seatCount` |
| `data/reservations.csv` | 预约记录 | `resNo,studentName,studentId,phone,seatNo,resDate,startTime,endTime,status,createTime` |

| `data/credit_score_logs.csv` | 信用分变动流水 | `logId,studentId,reservationId,changeValue,reason,createTime` |

- 编码 UTF-8，首行为表头，逗号分隔，日期 `yyyy-MM-dd`，时间 `HH:mm`，枚举保存英文常量名。
- `reservations.csv` 的 `createTime` 为预约提交时刻，格式 `yyyy-MM-dd HH:mm`；旧数据该列为空时按 `resDate+startTime` 兜底。
- 首次启动若文件不存在，由 DAO 初始化示例数据并写回。

## 九、前端交互约定（B-5）

1. 所有按钮事件只调用第六节中的 Service 方法，禁止在 UI 中写业务校验逻辑。
2. 调用返回 `BusinessException` 时，用 `JOptionPane.showMessageDialog` 展示 `message`。
3. 操作成功后重新查询列表刷新 `JTable`，不手工维护界面缓存。
4. 座位状态展示颜色：`AVAILABLE` 绿色、`RESERVED` 橙色、`OCCUPIED` 红色、`CLOSED` 灰色（B-5 实现时按界面主题确定）。
5. 学生界面需展示当前信用分；低于 80 分时预约按钮置灰并提示。

## 十、业务闭环（已确认）

1. 在线预约前校验学生信用分 >= 80，通过后锁定座位置为 `RESERVED`，生成 `BOOKED` 预约记录；
2. 签到登记时预约置为 `CHECKED_IN`，座位置为 `OCCUPIED`，立即写一条 `CheckinRecord`（`actualStart` 为签到时刻，`actualEnd` 与 `penalty` 暂空），使在座名单可实时查询；
3. 签退释放时：座位置为 `AVAILABLE`，预约置为 `CHECKED_OUT`，用 `CheckinRecordDao.update` 回填该条签到记录的 `actualEnd` 与 `penalty`；若实际结束时间晚于预约结束时间，扣学生 1 分；
4. 预约后未在规定时间内签到，系统判定爽约，扣学生 5 分，预约置为 `NO_SHOW`（与主动取消的 `CANCELLED` 区分），座位释放，并写一条 `CreditScoreLog(NO_SHOW, -5)` 流水；判定由 `ReservationService.handleNoShow(now)` 统一扫描执行，不依赖学生或管理员在界面上的操作；
5. 签退时若实际结束时间晚于预约结束时间，扣学生 1 分并写一条 `CreditScoreLog(LATE_CHECKOUT, -1)` 流水；
6. 签退时不做任何费用计算，全程免费；
7. 预约窗口：只能预约今天起 7 天内（含今天）的时段，不能预约过去的日期；超出窗口时 `ReservationService.reserve` 抛 `PARAM`，`message` 分别为「不能预约过去的日期」「只能预约 7 天内的日期」，前端日期选择器应同样把可选范围限制在这 7 天内。
